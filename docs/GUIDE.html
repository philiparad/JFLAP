SHIPPED-ARTIFACT ANALYSIS · VERSION 7.1

How JFLAP works

JFLAP is a collection of editors and experiments for formal languages and computation. A document represents a machine, grammar, expression, L-system, or pumping-lemma exercise. Operations add simulation or conversion tabs while retaining the original structure.

Two ways to use this project. The JavaScript workbench provides a new interface and independent algorithms. Original mode executes the supplied JAR through a JavaScript/WebAssembly runtime and preserves the original workflows. This guide explains the original feature families; the coverage matrix identifies which were independently implemented. It does not claim exhaustive testing of every original feature.

1. Documents and editing

The original chooser has twelve entries: Finite Automaton, Mealy Machine, Moore Machine, Pushdown Automaton, Turing Machine, Multi-Tape Turing Machine, Turing Machine with Building Blocks, Grammar, L-System, Regular Expression, Regular Pumping Lemma and Context-Free Pumping Lemma.

For machines, the editor consists of a toolbar and a drawing canvas. State (S) places a state. Transition (T) draws from one state to another; dragging to the same state creates a self-loop. Attribute (A) moves states and edits transitions. Delete (D) removes a state or transition; deleting a state also removes its incident transitions.

A state’s context menu sets the initial arrow, final double circle and auxiliary label. Each ordinary automaton has one initial state and may have several final states. Version 7.1 adds undo/redo, a configurable undo history, zoom, transition control points and several image exports. Notes annotate diagrams. The View menu can reflect, rotate, fit, save/restore and rearrange layouts, including circle, random, spiral, tree, two-circle and GEM layouts. These change the drawing, not the language.

Combine Automata copies the states and transitions of a second open automaton of the same type into a new automaton. It removes the second initial marker. It does not create connecting transitions, so it is not by itself language union or concatenation.

Sources: NewAction$NewDialog; MenuBarCreator; ChangeLog; editor help; combine help.

2. Finite automata

A finite automaton has a finite set of states and labeled directed transitions. A configuration records the current state and the unread input. A transition matches the beginning of the remaining input and consumes its label. A λ transition consumes nothing. An input is accepted if some computation consumes the entire input and ends in a final state.

JFLAP allows nondeterminism: several transitions can match the same situation. It also permits multi-character labels and character ranges such as [0-9]. The determinization workflow first expands multi-character labels into single-symbol transitions with intermediate states.

Highlight Nondeterminism finds states with competing transitions; λ transitions are treated as nondeterministic. Highlight Lambda marks empty-input edges. Reachability and useless-state helpers support analysis. Compare Equivalence compares the languages of two open FAs. The original documented method determinizes and minimizes them before comparing their structure. The new workbench instead explores pairs of DFA states and can return a distinguishing input.

Example: a loop reading 0 or 1 at q0, an additional q0→q1 edge on 0, and q1→q2 on 1 with q2 final recognizes strings ending in 01. On 1101, the simulator can keep scanning in q0 while also taking the suffix branch.

3. Pushdown automata

A PDA adds a stack. A transition contains input to read, string to pop, string to push. Each may be empty. It is enabled when the unread input starts with the read string and the top of the stack matches the pop string. The transition consumes input, removes the pop string, then pushes the replacement. The stack initially contains Z.

The run dialog chooses acceptance by final state or empty stack. Both require the input to be consumed. With final-state acceptance the leftover stack need not be empty. With empty-stack acceptance the final-state flag is not the criterion.

To recognize aⁿbⁿ, push an A for each a, change to a popping phase, pop A for each b, and accept only after the input is consumed and the stack reaches its bottom marker. The stack records an unbounded count that a finite automaton cannot store.

Direct bytecode evidence: PDAStepByStateSimulator initializes Z and performs prefix checks and pop/push updates.

4. Turing machines

A Turing configuration records a state plus one or more tapes and head positions. Input initializes the tape, with the head on the leftmost input symbol. Unfilled cells are blank. A transition specifies, for every tape, a symbol to read, a symbol to write and a move: L, R or S (stay). All tape conditions must match before the transition updates the tapes.

The artifact supports one through five tapes. A multi-tape transition updates all heads together. Nondeterministic machines can branch into several configurations. Tape modifications make these machines useful as transducers as well as language recognizers.

Preferences allow acceptance by final state, by halting, or either. There is also a preference controlling transitions out of final states and a preference allowing stay moves. In the original version, previously saved stay transitions remain functional when stay editing is disabled until they are edited.

Building blocks: a state can contain an inner Turing machine. Entering that state invokes its inner computation on the current tapes. The inner machine needs an initial state. Its final markers do not finish the outer computation; when it halts, the parent continues from the block state. Blocks may nest. The original interface lets a user right-click a state and edit the block.

The original simulator also contains compact read patterns and variable assignments. Bytecode exposes wildcard ~, negation and assignment handling. These are retained in Original mode; the independent web editor deliberately accepts literal single-symbol read/write entries and does not pretend to implement those shortcuts.

Turing-to-unrestricted-grammar conversion encodes tape/state configurations in grammar productions so derivations simulate computation. The original converter and its validation constraints are available in Original mode. This converter was identified in the artifact but not independently ported or exhaustively exercised.

5. Mealy and Moore machines

These finite-state transducers produce output while reading input. A Mealy transition carries input and output strings; taking the transition appends its output. A Moore state carries an output; entering a state appends that output. The initial Moore state contributes output before any input is read, as confirmed in the bytecode.

For a bit-complement Mealy machine, a single state can loop on 0/1 and 1/0. Input 0101 produces 1010. A parity Moore machine can output 0 or 1 according to the number of 1 symbols seen. These workflows report output strings rather than interpreting final-state membership as the primary result.

7. Grammars and parsing

A grammar is a list of productions left→right. Uppercase variables represent nonterminals in JFLAP’s common single-symbol convention. The first production determines the start variable. Empty right sides produce λ. General grammars can have several symbols on the left; context-free grammars have one variable on each left side; right-linear grammars restrict variable placement on the right.

Brute-force and user-controlled parsing

Brute-force parsing begins with the start variable and searches possible substitutions for a target string. The original performs pruning, supports pause/resume, and shows a successful derivation as a table or tree. Unrestricted rules may replace several adjacent symbols, so their derivation display can group multiple parents. A failure to find a derivation within a finite bound is not a proof of non-membership.

User-controlled parsing lets the learner choose productions and substitution positions rather than letting the search choose. Its role is to practice constructing a derivation. The original graphical controls remain in Original mode.

LL(1)

FIRST(A) collects terminal symbols that can begin strings derived from A, including λ when A is nullable. FOLLOW(A) collects symbols that can appear immediately after A, with $ for the end of input. The LL table chooses a production using the top variable and one input symbol. If a production’s right side can be empty, its FOLLOW symbols also select it. Conflicting entries indicate that this grammar is not LL(1).

The original exercise asks the user to fill FIRST, FOLLOW and table cells, validates entries, and offers Do Selected, Do Step and Do All. Parsing uses a stack initialized with the start variable: expand a variable from the table, or match a terminal against the input. Acceptance occurs when stack and input are both exhausted. The original can show ordinary/inverted parse trees and derivation strings.

LR / SLR

LR parsing works bottom-up. Item sets record positions inside productions, such as A→B·CD. Closure adds items for variables after the dot; goto moves the dot across a symbol. Shifts consume input and push a state, reductions replace a completed right side with its left variable, and goto chooses the next state. The original help labels this LR(1) but describes a workflow like SLR; the inspected generator uses FOLLOW-based reductions. The new implementation therefore labels its algorithm SLR.

The original exercise builds the item automaton and table interactively. Entries are shifts, reductions, gotos or accept. It allows resolving conflicting cells, warning that a chosen resolution may alter the accepted language. The web version exposes conflicts and refuses to silently resolve them.

CYK

CYK decides context-free membership using a grammar in Chomsky normal form. The bottom row records variables deriving each input character. Longer spans combine two shorter spans according to A→BC. The input is accepted if the start variable derives the entire span. The web workbench converts to CNF first and displays the chart and converted grammar.

8. Conversions and transformations

ConversionConstruction and educational workflow
NFA → DFAEach DFA state is a λ-closed set of NFA states. On symbol a, collect all a-successors and close again. Any set containing an NFA final state is final. The original validates user-entered sets and supports expand-group, expand-state and complete.
Complete DFAAdd a trap state and missing transitions for the alphabet. The trap loops on every symbol.
Minimize DFAPartition final and nonfinal states, then repeatedly split groups whose transitions reach different groups. The original displays a split tree and asks the user to construct the quotient machine, with hints and completion.
Regular expression → NFARecursively replace union, concatenation and star with small automata connected by λ edges. The original lets the learner select expressions, add required edges and finish steps.
FA → regular expressionCombine parallel edges with union, represent absent edges as ∅, and eliminate intermediate states. Eliminating k updates i→j with Rᵢⱼ + Rᵢₖ(Rₖₖ)*Rₖⱼ. The remaining start-to-final expression describes the language.
FA → regular grammarAssign a variable to each state. qᵢ —a→ qⱼ becomes Aᵢ→aAⱼ; final states get λ productions.
Right-linear grammar → FAVariables become states; a production A→aB becomes a transition A→B; terminal-only productions lead to a final state.
CFG → PDA (LL)Place the start variable on the stack. Replace a top variable using a grammar production, then match and pop terminals against input.
CFG → PDA (LR)Shift input symbols onto the stack and nondeterministically reduce right sides back to their left variables. Accept when the start variable remains and input is consumed.
PDA → CFGGrammar variables describe computations taking the PDA between states while removing a designated stack symbol. The original converter imposes a suitable transition form and guides production creation.
TM → unrestricted grammarEncode machine configurations and use productions to simulate tape/head changes, with acceptance cleanup. Original-only in this project.

Grammar transformation pipeline

  1. Remove λ productions: find nullable variables to a fixed point, then add productions covering omission of nullable occurrences.
  2. Remove unit productions: find chains A⇒B and copy B’s non-unit productions to A.
  3. Remove useless productions: eliminate variables that cannot derive terminal strings, then variables unreachable from the start.
  4. Chomsky normal form: replace terminals occurring in long right sides with variables, then split long sequences into binary productions.

The original panes let users select rules, perform one step, finish all steps and export completed results. Their original empty-word restrictions differ from the web converter, which preserves empty membership with a start rule. The web engine’s A–Z variable limit is explicitly reported when exhausted.

9. L-systems

An L-system has an axiom, rewriting rules and drawing parameters. All symbols are separated by spaces: g f g g is four tokens; gfgg is one. Each generation replaces symbols simultaneously. Multiple applicable productions make a stochastic choice. A context rule begins with the index of the rewritten symbol: 1 a X b → g rewrites X only when surrounded by a and b. An empty replacement deletes the token.

The renderer uses a turtle position and orientation in 3D, projected orthogonally onto a 2D display. The original uses a 2D drawing surface and does not perform full 3D occlusion/depth sorting. View rotations expose 3D structure.

Commands can take an argument such as g(distance*2). Expressions support addition, subtraction, multiplication, division, powers, parentheses and parameter names; an undefined variable is zero. Original colors support named values and numeric RGB or HSB triples. The new renderer’s hue shortcuts and color vocabulary are simplified; use Original mode for exact original color semantics.

10. Pumping-lemma games

The pumping lemma is a quantified statement, not a shortcut that classifies languages by testing a few strings. In the regular game, choose a pumping length m and a word w in the language with |w|≥m. Split w=xyz with |xy|≤m and |y|>0. Pump to xyⁱz. In the context-free game split w=uvxyz, require |vxy|≤m and |vy|>0, and pump uvⁱxyⁱz.

The original offers human-first and computer-first roles, language-specific witness choices, decompositions, pumping responses and case explanations. One side tries to defend a decomposition for all exponents; the other tries to find a counterexample. A single bad split does not prove nonregularity: the adversary must defeat every permitted split for a suitable witness at every proposed pumping length.

Regular exercise library

The 13 classes cover even-length unary words; #a<#b; even positive powers of ab; (ab)ⁿaᵏ with n>k; aⁿbⁿ; even palindromes; bba(ba)ⁿaⁿ⁻¹; b⁵w with a linear count relation; bᵏ(ab)ⁿ(ba)ⁿ; aⁿbᵏ with parity conditions; aⁿbᵏcⁿ⁺ᵏ; constrained aⁿbˡaᵏ; and b⁵w with a modular count relation. Some are regular and some are not, intentionally.

Context-free exercise library

The 13 classes cover aⁿbⁿ; aⁿbⁿcⁿ; aᵏbⁿcⁿdʲ with j≠k; repeated aⁿbʲ blocks; aⁱbʲcᵏ with i>j,k; count comparisons over {a,b,c}; ww; ww₁wᴿ with equal component lengths; ww₁wᴿ with a minimum middle length; w₁bⁿw₂ count restrictions; four c-separated components; and a centered vvᴿ substring with balanced outer a counts. The shipped class names and guide coverage identify all 26 concrete exercises.

The web workbench supplies explicit membership predicates, validates decompositions, generates examples and tests exponents. Its computer split helper only tests exponents 0, 2, 3 and 4. It is labeled a bounded aid and never reports a universal proof. Original mode retains the original language-specific game strategies and case panels.

11. Files, preferences and help

JFLAP XML uses a structure root and a type. Automata contain states, initial/final markers and transitions; FA transitions contain read fields, PDA transitions add pop/push, Mealy transitions add transout, Moore states add output, and Turing transitions include per-tape read/write/move fields. Grammar documents contain productions; expressions contain an expression field; L-systems contain axiom, productions and parameters.

Original file actions include New, Open, Save, Save As, Dismiss Tab, Close, Quit, printing and several image formats. The artifact also contains older codec implementations. Exact historical compatibility and nested block references are handled by Original mode. The web codec supports common XML types and JSON but does not claim universal backward compatibility.

Original mode uses a virtual filesystem. Imported files are placed at /str/; writable persistent files belong under /files/. A download control brings a saved file back to the host. Browser storage can be cleared by the user or browser, so download important work. The independent workbench automatically saves its workspace locally and uses normal browser file downloads.

Preferences include the empty-string glyph, color choices, undo amount and Turing behavior. Help is contextual: the current operation determines the help page. The bundled help explicitly lacks coverage for some newer actions. This project includes the original help index and its figures, alongside this guide.
